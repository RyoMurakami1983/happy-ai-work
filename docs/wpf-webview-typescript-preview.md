# WPF・WebView2・TypeScriptの試用

2026-11-09。happy-preview 0.8.0へ追加。

## 目的

既存のwpfとtypescriptを補い、Web UIとC#の通信、権限、非同期処理、寿命、負荷の接点を扱う。短歌・俳句の観察と推敲を、意味を残して記述を絞る方法として用いる。

## 対象アプリの改善基準

所有者が指定した次の基準を、対象アプリの改善と検証に使う。スキル比較の採点指標ではない。

1. 1秒以上の応答遅延は改善対象とする。受付と完了を分けて測り、進捗表示だけで解決扱いにしない。
2. 取消しても入力と条件を残し、再操作で入力し直さずに済む。
3. 切断前の入力と進捗を保存し、復旧後は確定状態を確認して未完了部分から再開する。

性能の測定条件、保存の範囲、復旧する障害を実装前に明らかにする。入力の自動保存と業務上の確定を分け、二重保存や秘密情報の不要な永続化を防ぐ。

## 代表的な模擬依頼の作者確認

これは記述に沿った机上確認であり、独立評価や実アプリでの再現試験ではない。

| 依頼 | 適用した判断 |
|---|---|
| クリックから1.2秒無反応 | 受付・処理・表示を分けて測定し、1秒以上を改善課題として残す。spinner追加だけで完了にしない。 |
| 書出しを取消すと条件が消える | operation取消しとdraft破棄を分け、再入力なしの再操作と遅着応答を確認する。 |
| 保存済みだが応答前に切断 | operation IDから確定状態を照会し、同じ書込みを再送しない。 |
| host再起動後に続きを進めたい | メモリ外のdraft・journalと確定状態を照合し、障害範囲ごとに再開を確認する。 |
| WPFの色だけ変えたい | 本スキルの対象外とし、wpfへ委ねる。 |

## 制約と試用時の確認

形式・参照検証と上記の机上確認を対象とする。実務での有用性、自動選択、実アプリの1秒未満応答や障害復旧は未検証。新しい基準をアプリで達成済みとは扱わない。

試用では対象アプリの操作、データ量、端末、改善前後の結果、再入力と二重保存の有無、未対応の障害を残す。実データの書込みは利用者が依頼した範囲に限る。個人情報や未加工の実案件資料は公開記録へ含めない。

個人用同名スキルから移行する場合、previewの導入を確認してから個人用を無効化・退避する。plugin cacheを直接編集しない。本追加では個人用を削除しない。

## 初版の検証結果

- 公式skill validator: PASS。
- repo validator（参照・配布規則・評価記録を含む）: PASS。
- Ruff、ty、git diff --check: PASS。
- 指定入口 `uv run --script scripts/validate_quality.py`: 全体はFAIL。255 tests、1 failure、6 errors、5 skipped。
- 失敗は既存のproject-protectionテストで発生。観測した原因にはshの未検出、Windows symlink作成権限不足、cp932での出力decode失敗がある。全件を環境原因と断定したり、skipを成功へ読み替えたりしない。
- 検証中にmainの`9d137f7`へfast-forwardした。開始時`9667c28`とのtree差分はなく、追加内容を保持した。

対象アプリへの実装・性能測定・復旧試験は、このスキル追加作業では行っていない。

## 完了した開発からの引継ぎ

通常起動側の管理記録を既存APIで再接続し、配布物の整合性・引数なしの通常起動を確認して解決した事例を反映した。アプリ本体の更新は不要だった。実行環境による参照先の違いを切り分け、履歴を持つ記録を無条件に上書きしない手順として一般化した。利用者のパス、生の管理記録、非公開repoへの参照は含めない。

この引継ぎは既存の完了記録の確認であり、アプリの再操作や新しい受入れ試験ではない。追記後はrepo validatorと差分検査を再実行し、先の全体テスト失敗は未解消として保持する。
