# 着手判断と任意の開始時設定の責務をhomeとskillsで分担する

Status: Accepted（2026-09-26、独立設計レビュー後に利用者が「commit後に実装して外部レビューして下さい」と承認）
Date: 2026-09-26

## 背景

相談・Issueの選択から実装へ進む誤解を減らす必要がある。一方、明確な局所修正に毎回重い工程や再承認を要求すると、既存の自律性を損なう。利用者はPRD短縮経路を維持し、理由と実装許可の確認を求めた。また、Yohakuを希望者だけが新しい会話の最初から適用し、通常更新後も選択を保持できることを求めた。[PRD 009](../prd/009_PRD.md)を要求の正本とする。

## 決定

1. homeは、相談・対象選択・実装許可を区別する短い共通方針を所有する。具体的な工程の手順や用語集はskills側に置く。
2. to-prdは短縮の成立条件と省略理由・許可の引き継ぎを、implementは実装許可と範囲の確認を所有する。同じ規則全文の複製を避け、送る側と受け取る側の責務を明示する。
3. 垂直スライスの定義と短縮条件はhappy-coding内の条件付きreferenceを正本とする。単一sliceを低riskや設計不要と同一視しない。
4. home-bootstrapは、選択可能かつ本文を参照できるYohakuについて利用者の希望を確認する。基本方針と任意の開始時設定は既存の一つの管理領域内に合成し、状態を通常更新で保持する。
5. Yohakuは任意のpreview skillのままとし、利用不可でも基本方針を利用できる。配布変更、インストール更新、実home適用を分ける。

保存形式・CLI・失敗時の詳細は[設計009](../design/009_TECHNICAL_DESIGN.md)に置く。将来の汎用設定基盤まで導入する判断ではない。

## 既存判断への影響

- [設計005](../design/005_YOHAKU.md): 「開始指示をAGENTSへ追加しない」を、利用者が希望し承認した場合に限って更新する。会話内継続のために勝手にhomeを編集しない境界は維持する。
- [設計008](../design/008_TECHNICAL_DESIGN.md): homeに共通判断を置く責務は維持する。implementには別責務として許可の受け取り確認を追加する。「6項目固定」は基本方針と任意設定の構成説明へ更新する。
- ADR 0003のfinalizationとADR 0004の任意preview配布は維持する。Constitutionの価値・優先順位は変更しない通常の運用改善として扱う。

採用前のProposed版は文書commit `51d65bd`に保存した。過去の設計記録は保存し、必要な箇所に後続判断への参照を加える。採用判断は実装の検証成功や実homeへの適用を意味しない。

## 選択肢・不利益

全初回依頼を止める方式は明確な修正への過剰停止を生む。implementだけで制御するとskill未起動時に届かない。homeへ全詳細を集約すると無関係な依頼にも負担がかかる。このため上記の責務分担を選ぶ。

代わりに、工程間のhandoffと任意設定の保持処理を保守する必要が生じる。旧home-bootstrapへのdowngradeでは新しい任意設定が消える可能性があるため、差分とbackupで復元可能性を確保する。自然言語の指示が全実行で守られる保証とは扱わず、固定した隔離scenarioで行動を検証する。

## 採用確認

設計の独立レビュー、利用者による具体的な実装範囲への合意、後続の行動評価と品質確認を区別して記録する。レビューPASSや文書作成の承認だけで実装を開始しない。評価結果の履歴を書き換えず、採用後の効果も未測定ならそのまま示す。
