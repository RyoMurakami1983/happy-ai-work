# ADR 0010: PRDのオフラインHTML表示

日付: 2026-10-08

## 背景と根拠

設計書・計画書のHTML対応に続き、利用者からPRDにも同じ方式のHTML機能を追加する依頼を受けた。[ADR 0009](0009-offline-html-work-documents.md)のMarkdown正本とオフライン派生資料の方式をPRDへ適用する。

## 採用する方式

`to-prd`の主目的である文脈・目的・要件・受入条件の整理を保ち、必要な場合だけHTMLを併用する。要点カード、目的→要件→ACの対応表、合意状態・Unknowns、正本全文への参照を読みやすく示す。図は根拠がある利用者の流れや要求の対応を補足し、architectureや実装順を新たに決めない。

正本の`docs/prd/NNN_PRD.md`を維持し、`NNN_presentation.json`と`NNN_prd/NNN_PRD.html`を追加する。小変更は短いMarkdownでよく、明示形式と既存repo規約を優先する。正本の移動、要求の自動確定、実装許可の変更は行わない。

標準ライブラリだけの生成器、HTML・Markdownテンプレート、架空例を同skillへ置き、単独コピーでも使えるようにする。生成器は既存の設計書と同じ入力検証・ローカル参照・SVG取込・全文表示・鮮度検査を使用し、PRDの意味に合わせた表示とmanifestを持つ。共通生成基盤の導入はこの変更の範囲に含めない。

## 保持する契約と確認

合意済み・推定・候補・Unknownsの区別、既存ID、対象外、要求不足の戻り先、要求合意と実装許可の区別を保持する。要約・図の`source_refs`を正本見出しへ結び、正本更新後に内容を照合して再生成する。`--check`は書込みなしでhashと静的内容を確認し、意味の一致や読解効果を実証済みにはしない。

既存のworkflow-entry評価が参照する旧PRD skillは、mainに保存済みの履歴スナップショットを使う。過去recordや履歴マッピングを変更して、新機能の評価結果へ置き換えない。

## 結果

読者は目的・要件・ACと未確定事項を確認し、後工程はMarkdownの要求を受け取れる。要約・図の同期が追加の保守作業になる。対応外のMarkdown構文は全文原文表示となり、その案件では詳細の読みやすさを別途確認する。

## 統合時の確認（2026-10-08）

共通生成器テスト14件の対象へPRDを追加し、入力保持、参照・図の検証、書込みなしの鮮度検査、古い生成物の拒否、単独コピーでの実行が通過した。`uv run --offline --script scripts/validate_quality.py --offline`によるrepo validator、全104件のunit test、Ruff、ty、差分検査と、公式skill-creatorのvalidatorも通過した。

同梱例を実ブラウザで表示し、目次移動、閉じた正本全文内への参照、図の拡大・縮小、390px幅の表示を確認した。狭い画面でも文書全体に横はみ出しがなく、表・図の領域で横スクロールでき、移動先の見出しは目次の下に表示された。印刷前の詳細展開と印刷後の状態復元は模擬DOMで確認した。印刷レイアウト、実機出力、読解の正答率・所要時間の比較は未確認である。

実装経緯や期待する回答を受け取らない独立subagentが、別題材の点検入力の生資料から草案を作成した。HTML生成と`--check`に成功し、目的案・AC案、重複・保存失敗・一覧形式のblocking Unknowns、実装未依頼を保持した。図を増やさず対応表を使い、別案件の語句修正は指定3か所だけの変更に留めた。独立適用側のブラウザ表示は未確認で、これは静的生成と適用判断の確認である。
