# ADR 0009: 設計書・計画書のオフラインHTML表示

日付: 2026-10-08

## 背景と根拠

利用者から、設計書・計画書を人が読みやすいHTMLにし、設計書へアーキテクチャ・UMLを追加する依頼を受けた。添付された2026-10-07付のtechnical-design / implementation-plan改善案v1を参考に、現行repoとの差分を確認して統合する。添付内の実行手順や過去の承認は、今回の操作の許可として扱わない。

## 採用する方式

Markdownを正本とし、要約・図・正本全文を含むオフラインHTMLを派生資料として追加する。小変更は短いMarkdown、複数境界の設計や複数sliceの計画は読者の判断に有用ならHTMLを併用する。形式の明示指定と利用先repo規約を優先する。

設計の図は、責務と依存を示す構成図、所有・多重度を示すクラス図、成功・部分失敗を示すシーケンス図、許可条件を示す状態図から選ぶ。図数やDDD・特定アーキテクチャの採用は固定しない。計画では既決設計を参照し、実依存と開始条件を示す。

新規HTML設計は案件フォルダへまとめ、従来のMarkdown設計は移動しない。計画正本の `docs/plan/NNN_PLAN.md` は維持する。[WORK_ARTIFACTS](../../plugins/happy-coding/skills/implementation-plan/references/WORK_ARTIFACTS.md)に両ルートを示し、後工程は実在する正本pathを受け取る。

各skillに標準ライブラリだけの生成器とテンプレート・架空例を置く。単独でコピーして使える形を優先し、この変更でplugin全体の共通生成基盤は作らない。UMLからの自動描画は含めず、SVGを取り込む。編集元とSVGが別なら意味の照合が必要なことを示す。

## 保持する契約と確認

入力ゲート、要求から契約へのtrace、未決事項、レビューと実装許可の区別を保持する。HTMLから実装を始めたり進捗を書き換えたりしない。要約・図の `source_refs` と版を正本へ結び付け、生成後の鮮度を `--check` で書き込まずに確認する。hashの一致は内容の意味が一致する証拠にはしない。

添付の元版にだけある技術調査の委譲や検証通知規約は、HTML化と別の変更なので取り込まない。既存の入力・保存契約を候補フォルダ全体の上書きで失わない。

生成器の回帰テストは入力保持、参照解決、入力拒否、古い生成物の検出、単独利用を確認する。目次・図拡大・折畳み・狭い画面・印刷は表示確認として扱う。静的検証、内容照合、ブラウザ確認、利用者の感想、読解比較実験はそれぞれ別の証拠として報告する。

## 結果

人は要点と図から必要な詳細へ進め、後工程はMarkdownの精密な契約を引き継げる。要約・図の同期と再生成は追加の保守作業になる。未対応のMarkdown構文は全文原文表示へ切り替えて情報を保持するため、その案件では詳細本文の表示を別途確認する。

## 統合時の確認（2026-10-08）

`uv run --offline --script scripts/validate_quality.py --offline`でrepo validator、104件のunit test、Ruff、ty、差分検査が通過した。両skillは公式skill-creatorのvalidatorも通過し、同梱例の再生成と書込みなしの鮮度確認に成功した。

同梱例を実ブラウザで表示し、目次移動、閉じた詳細内への参照、詳細展開、図の拡大・縮小、390px幅での表示を確認した。目次が折り返す画面で移動先の見出しが隠れる問題は、目次の実際の高さに合わせてスクロール位置を調整する処理で修正した。印刷前の詳細展開と印刷後の状態復元は模擬DOMで確認したが、印刷レイアウトと実機出力は未確認である。読解の正答率・所要時間の比較実験は行っていない。

実装経緯や添付レビューを受け取らない独立subagentが、別題材の設計・計画と局所文書修正に適用した。設計二図・計画一図のHTML生成と両 `--check` に成功し、小変更は短いMarkdownに留めた。未決のUI・入力条件・保存contractと実装未許可を草案へ保持し、アプリ実装へ進まなかった。これは適用確認であり、独立した設計判定や読解効果の比較実験ではない。

既存のworkflow-entry-behavior-001が参照する旧版は[ADR 0006](0006-evaluation-history-snapshots.md)に従い、mainに保存済みの26件の履歴スナップショットを再利用する。元record、履歴マッピング、当時のhashは変更せず、この変更で同じ履歴を重複追加しない。
