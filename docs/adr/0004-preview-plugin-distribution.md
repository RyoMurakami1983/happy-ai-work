# 公式の配布チャネルが整うまでプレビューを別pluginで配布する

Status: Accepted
Date: 2026-09-06

## 背景

新しいskillは静的検証と模擬依頼を通っても、実作業での有用性が未確認なことがある。利用者が試せる経路を用意し、通常配布のskillと実利用検証中のskillを区別する。所有者は、今回のゲーム制作2skillを別のプレビュー用pluginで試用し、公式が正式なpreview／beta機能を提供するまでこの方法で配布する方針を採用した。

公式資料には[ローカル試用・repo marketplace・Git refによる配布](https://developers.openai.com/plugins/build/plugins)がある。一方、2026-09-06に確認した範囲では、skill単位の正式なpreview／betaチャネルは確認できていない。「Preview」は本repoの運用上の表示であり、Codex固有のチャネル機能ではない。

## 決定

- 通常配布の`happy-core`、`happy-coding`と別に、試用用`happy-preview`を配布する。marketplaceでは既存2項目の後へ追加し、`AVAILABLE`による任意導入とする。
- 構想段階は`incubator/`、基本検証を通り試用できる段階は`happy-preview`、実利用で確認した段階は目的に合う通常pluginへ置く。`incubator/`に`SKILL.md`やmarketplace entryを置かない規則は維持する。
- プレビューへ入れる前に、独立した目的とtrigger、実行可能な手順、参照・形式検証、代表的な模擬依頼、既知の制約、試用時に確認することを揃える。実利用未検証の状態を明記し、安全・評価整合性の基準は緩めない。
- plugin表示とskillの説明にプレビューであることを示す。導入した後のskillは通常の自動選択を維持する。プレビューという理由だけで明示呼出し専用にしない。
- 同じskillを通常pluginとpreviewへ重複配布しない。正式化はコピーではなく移動とし、移動先と必要な導入変更を案内する。skill名は可能な限り保持するがpluginのnamespaceは変わる。
- バージョンはpluginの配布物を識別する。番号だけで品質段階や自動更新の除外を表すと仮定せず、プレビューの分離はpluginの識別子と導入先で行う。

## 正式化と撤回

試用前に対象skillの期待する成果と観察条件を決める。異なる実作業で複数回使い、成果物・困った点・修正後の再確認を残す。既存の独立目的・trigger・検証境界の条件を満たし、残る制約を示して所有者が通常配布への採用を判断する。模擬回答やテスト成功だけで実利用済みにしない。

期待する価値が出なければ修正して継続、保留、配布から撤回を選べる。過去の評価結果は書き換えない。公開記録は必要最小限にし、個人情報や実案件の未加工データを含めない。撤回・正式化時は、既存インストールが自動的に消えると仮定せず、更新・無効化・導入先変更の案内を付ける。

## 公式機能が提供されたとき

公式のpreview／beta配布機能を確認できた時点で、このADRを見直す。名称の追加だけでなく、任意導入、通常版との識別、更新先、正式化・撤回の経路、既存利用者の移行を満たすか確認する。対応が十分なら後続ADRで移行を決め、利用者へ案内してから移す。機能発表だけで自動移行はしない。

## 影響

利用者は通常pluginを更新するだけでは試用skillを受け取らず、`happy-preview`を選んで試せる。代わりに、正式化時の移動と導入案内を保守する必要がある。同じplugin内のBeta表示だけでは導入先を分離できないため採用しなかった。既存plugin全体を複製する方式も、二重保守を避けるため採用しない。

## 2026-11-06: 短歌と俳句の限定した通常配布判断

通常の昇格条件は上記のまま維持する。今回に限り、所有者が短縮前後の本文を確認して短縮前を選び、`tanka-to-haiku`をhappy-coreへ移すことを明示承認したため、この未短縮本文の移動を許可する。適用先はhappy-core 0.5.0への当該移動のみとし、他skillや今後の本文改訂の昇格条件には広げない。

異なる実案件での複数回有用性確認は未完了であり、通常の昇格gateを満たしたPASSや実利用済みという評価へ変更しない。独立した目的・trigger、事実と振る舞いの保持・指定形式・詩型を強制しない境界、形式検査、限定評価、元本文の一致確認を判断材料とする。これは所有者による今回限定の配布判断で、短縮率による昇格ではない。

[移動する本文・導入変更・検証限界](../design/018_SKILL_COMPRESSION_AND_TANKA_MIGRATION.md)を公開記録とする。通常配布後も効果・困った点・修正後の確認を残し、意味や振る舞いの欠落が観測された場合は次の配布前に再評価する。必要なら修正・保留・撤回を判断する。この承認を他skillの未測定や安全・評価整合性の緩和へ流用しない。
