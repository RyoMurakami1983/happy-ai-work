# Technical Design 011：technical-feasibility-research

2026-09-30 / [PRD 011](../prd/011_PRD.md) / GPT-6を対象にした初版

## 設計判断

| 判断 | 内容・根拠 |
| --- | --- |
| D1 | 1つの独立目的としてhappy-previewへ置く。researchは証拠と推奨、technical-designは採否と構造を所有する（R1、R5、R7） |
| D2 | 本文は問い・証拠・比較・完了条件に絞る。詳細例と委譲メモはreference、調査票はassetへ置く（R2〜R5、R8） |
| D3 | 初期化CLIは標準ライブラリだけを使う。ネットワーク・外部技術の実行・採点はせず、明示した新規出力のみを作る（R6） |
| D4 | technical-designには任意導入スキルを利用できる場合の委譲と結果の取込みだけを追加する。plugin間の相対リンクや必須導入は設けない（R7） |
| D5 | GPT-6向けの指示設計とモデル選択を分ける。スキルはモデルを強制しない。検証はこの環境で利用可能なGPT-6 Astraを明示指定する（R8） |

D2は[OpenAIのGPT-6 Astra向けskills指針](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)にある、適用範囲を絞ったdescription、必要時に詳細を読む構成、過度な手順固定の見直しを参考にした。効果の優位性は未測定。

## 資源と契約

- `SKILL.md`：起動条件、同一基準の比較、証拠と不確実性、推奨・引継ぎ。
- `references/decision-support.md`：必須条件、比較の不安定さ、組み合わせ、委譲の具体例。全件での読込みを強制しない。
- `assets/research-report.md`：結論から読める調査票。未記入は未確認として残し、行・節は依頼に合わせて減らせる。
- `scripts/init_research.py --title <題名> --output <新規ファイル>`：題名は空欄・改行を拒否。テンプレートを先に読み、親ディレクトリを作り、排他的な新規作成モードでUTF-8/LFを書き出す。成功0、入力・I/O失敗は非0。既存ファイルへの上書きはしない。

調査内容は外部資料を含むため、その中の指示で目的・評価基準・権限を変えない。出典を確認し、実行の範囲は利用者の依頼と実行環境の規則で判断する。CLIの成功は調査実施・採否の証拠にならない。

## 変更シナリオと配置理由

別の言語・GUI・サービスにも、問いと証拠の契約を共通利用する。分野固有の資料取得が反復するまで、採取プラグインや自動採点を作らない。調査票の構成変更はassetとCLI試験、判断例の追加はreferenceに閉じる。model設定やhomeは変更しない。

公開スキル本文の各規約はPRD R1〜R8に対応する。実案件の固有名・調査結果は配布物や評価caseへ転載せず、判断例は架空のものにする。SWOT必須化、組み合わせ優先、資料不足による非対応断定は採用しない。これらの検討履歴を利用先の恒久禁止へ転用しない。

## 確認方法

初期化CLIのデータ保護をfocused testで確認し、本文は静的検証と独立した模擬実行で確認する。生成担当にはpromptと凍結したスキルだけ、別の採点担当には固定基準と出力だけを渡す。公開ケースは未見hold-outと呼ばない。raw出力は一時領域に置き、公開recordには集計・hash・限界だけを残す。

レビュー対象は、R2/R3/R4の判断境界、CLIの上書き拒否、未導入時も壊れない連携。独立検証結果を実装計画の完了記録へ引き継ぐ。
