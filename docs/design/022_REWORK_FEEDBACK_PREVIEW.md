# 実装・設計の手戻りfeedbackをPreviewで試す

Date: 2026-11-09 (UTC)
Status: 所有者が試用実装を依頼。実利用効果は未確認。

## 判断概要

`implement`と`technical-design`に、再利用できそうな手戻りだけを拾う短い導線を置き、整理手順は`happy-add-issue`のreferenceへ集約する。通常の完了条件は変えず、元の仕事を先に返す。原因の誤帰属、Issueの増殖、作業の中断を主要riskとし、観測事実と仮説・反対仮説の区別、同じ出来事の集約、投稿前確認で抑える。

[試用Issue #80](https://github.com/RyoMurakami1983/happy-ai-work/issues/80)で継続追跡する。

## 根拠と対象

所有者は、手戻りから学ぶ案への助言を含めてIssueへ記述し、実装・設計skill内でPreviewと明示して試すよう依頼した。採用範囲は2スキルの条件付き導線と、既存のfeedback整理先の拡張。全スキルへの一律適用、skill自動改変、無断投稿、マージ、利用者端末のplugin更新は含めない。

- `implement`／`technical-design`: 実際の手戻りから候補があるときだけ渡す。候補なしの報告や追加確認は増やさない。
- `happy-add-issue`: 原因を断定せず、具体例・証拠・不確かさを残して一候補へ整理する。既存の固定投稿先・匿名化・重複検索・preview確認は維持する。
- `tanka-to-haiku`: 内容の核と構造を整える既存の共通skill。本文を変更・複製せず、原因証明や詩型を目的にしない。

この配置は既存skillの役割内にある条件付き機能で、独立目的を持つ新しいskillではない。2つの通常skillを`happy-preview`へ複製せず、既存skill内に試用表示を置くという今回の依頼に限定する。新規skillの配布・昇格は[ADR 0004](../adr/0004-preview-plugin-distribution.md)の条件を変えない。利用者が望まなければ候補化を省略でき、coding単独導入ではcoreの導入・確認待ちを発生させない。

## 受入条件と確認ケース

1. 再利用可能な修正: 元の成果を先に返し、観測事実・原因仮説・反対仮説・小さな改善候補を区別したdraftを提示できる。
2. 通常のTDD、誤字、一度きりの好み: 自動で候補化せず、追加の質問・Issueを増やさない。
3. 原因不明: skill原因と断定せず、不明点と反証可能性を保つ。
4. 設計と実装の同一事象・既存Issueあり: 一候補へ集約し、既存URLへの接続案だけを示す。
5. 投稿保留・辞退・結果不明: 再提示・再帰呼出し・重複投稿をしない。
6. core未導入・試用不要: 元の作業を閉じ、導入を強制しない。
7. 公開できない証拠・重複検索不能: 安全なdraftまたは候補化見送りに留め、未確認を隠さない。
8. 元の仕事が未完了: blocker・再開点を先に渡し、候補の整理で作業を完了扱いにしない。

形式・参照・配布versionは静的検査で確認し、上記は独立した模擬依頼の確認と区別する。静的検査や模擬回答は、実利用での手戻り削減の証明ではない。固定文言との一致だけを検査する専用testや新しい評価frameworkは追加しない。

## 試用・判断・撤回

Issue件数を成功指標にしない。採用できる候補、根拠の追跡しやすさ、誤帰属、重複、元の仕事への中断負担、適用後の同種手戻りを見て、継続・修正・撤回・拡張を判断する。少数例で因果効果を断定せず、試用の導入PRだけでは継続追跡Issueを閉じない。

[Issue #73](https://github.com/RyoMurakami1983/happy-ai-work/issues/73)は短歌と俳句の実装・設計・Issue適用の長期評価を所有する。今回の手戻り候補化と混同せず、同Issueの未実行評価を実行済みにしない。

変更pluginはhappy-core 0.5.3、happy-coding 0.8.1。撤回時は2スキルの導線、happy-add-issueの条件付き節・reference、READMEの案内を外し、新しいpatch versionを配布する。既存のIssue投稿手順、実装／設計の完了契約、tanka-to-haiku本文は維持する。repoの変更だけで利用者の既存pluginや会話へ反映されたとは扱わない。

- これは限定した合成ケースの指示レビューであり、独立generator／blind graderを備えた比較評価や実利用での効果測定ではない。実利用での候補採用・手戻り削減、plugin導入後の実際の自動選択は未確認。
