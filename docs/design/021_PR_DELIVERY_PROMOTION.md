# PR Deliveryの通常配布と検証の自動進行

Decision: Accepted（2026-11-09、所有者が昇格と検証方針の反映を明示依頼）。[ADR 0004](../adr/0004-preview-plugin-distribution.md)に基づく通常配布判断。Constitutionの原則・安全境界の変更はない。

## 採用と配布

`pr-delivery`をhappy-previewからhappy-codingへ移す。マージ許可、最新head/checks、条件付き削除、未保存変更と他作業の保護は変えず、試用表示だけを外す。codingは0.8.0、previewは0.7.0とする。評価用snapshotと過去recordは変更しない。

所有者の実開発チャットを確認し、異なる3プロジェクトでマージからbase同期・対象branch整理までの完了を観測した。確認した範囲では、再承認による停止や再指示の要求はなかった。未コミット資料を保持して完了した例、重大指摘を修正して再レビュー後に完了した例もある。読込版を確認した例はpreview 0.3.1と0.4.1で、全環境・全版の成功率や自然文自動選択を保証しない。個別案件の識別子・未加工ログは転載しない。

CI待ちでは変化の少ない報告が反復した。所有者からは細かなテストごとの確認が負担だったというfeedbackがあった。後者をpr-delivery固有の不具合と断定せず、実装・修正・.NETから参照される共通検証ガイドで扱う。

更新時はhappy-codingを導入・更新し、happy-previewも更新する。明示呼出しは`happy-coding:pr-delivery`。旧インストールの自動削除を前提にせず、旧skillの登録が残れば無効化・削除する。他のpreview skillを使う場合はplugin全体を無効化しない。配布比較ツールでcoding側の本文・UI設定・条件付き削除referenceと、preview側の旧directory不在を確認する。

## 検証の許可と進行

所有者の合意は「対象・影響・権限を限定して任せ、その範囲は自動で進める」。実行規約は[共通検証ガイド](../../plugins/happy-coding/skills/implement/references/verification-communication.md)に置く。テストごとの再承認を省き、範囲外の影響だけを確認する。管理者権限は必要な操作に限定し、OS・実行基盤の承認や拒否を迂回しない。今回の依頼は端末全体の管理者権限や任意の本番試験への包括許可ではない。

## 所有者の社内利用向け暫定AC

所有者が開発を依頼する社内利用アプリ（Webを含む）の応答性について、次を暫定基準v1とする。対象案件のPRD／検証計画へ採用して使い、公開plugin利用先へ暗黙適用しない。

- 16GBメモリ・Core 5程度のPCで、通常利用時に約5秒以上の操作停止・応答遅延が発生しない。
- 代表操作、通常のデータ量、併用アプリ、実際のCPU・OS・ブラウザー、Webの通信条件、観測期間を試験前に記録する。Core 5は厳密な機種指定ではないため、異なる端末の結果を同等性能と断定しない。
- 入力から操作可能な応答までの時間と停止の有無を観測する。約5秒以上を観測すれば不合格。未計測・境界が判別できない結果は未確認とし、合成テストだけで実環境合格としない。機能・データ保護等の既存ACは別途満たす。
- 基準未満でも実利用で不快さがあれば見直す。改訂は次の試験の基準として記録し、過去の不合格を後から合格へ書き換えない。

テスト実行中も利用中のPCの通常操作を妨げないよう負荷・並列数を抑える。今回の文書・配布変更では、この端末条件でのアプリ性能試験や管理者権限の試験は実施しない。

## 検証範囲

移動前後の手順・条件付き削除referenceの照合、形式・参照・配布重複検査、既存の条件付き削除試験と配布更新試験、repo品質検査を行う。移動後pluginの新しい会話での読込と、社内環境の性能ACは別の確認であり、ローカル品質検査の成功に含めない。

2026-11-09のローカル検証結果:

- 手順は試用表示以外一致し、条件付き削除referenceは内容一致。公式quick_validateはpr-delivery／implementとも成功。
- 条件付き削除4テスト成功。配布更新20テストは成功扱い、うちシンボリックリンク関連3ケースは権限条件でskip。旧preview版の残存検出も確認。
- `uv run --script scripts/validate_quality.py`のrepo validator、Ruff、ty、diff checkは成功。全237テストは1 failure・6 errors・5 skipsで、全体成功ではない。失敗は変更していないproject-protection試験の`sh`未検出、実symlink権限不足、一時EXE削除のアクセス拒否。今回の差分が原因とする証拠はなく、元revisionでの再実行は未実施。
- 検査中に本作業で旧検証文書へ採用記録のリンクを追加したため、worktree不変検査も失敗した。生成物は最終差分で確認し、初回uv実行で生成したlockfileと一時cacheは除去した。

配布変更はローカルで準備済み。公開・導入更新や上記の環境依存試験の解消まで完了したとは扱わない。
