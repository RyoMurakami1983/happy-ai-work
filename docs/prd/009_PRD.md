# PRD 009: 実装開始の合意と任意のYohaku開始時適用

Date: 2026-09-26
Status: 要求・変更方針は会話で合意済み。文書作成を承認済み。実装開始は未承認。

## Context / Problem

利用者は「issue対応したい。」→「35と29できますか？」という相談・対象選択から実装へ進んだことを問題とし、要求整理、PRD、必要な設計・設計レビュー・計画を先に進める方針を求めた。Issue [#35](https://github.com/RyoMurakami1983/happy-ai-work/issues/35) と [#29](https://github.com/RyoMurakami1983/happy-ai-work/issues/29) は今回の再現入力であり、その機能実装は本案件の対象外。

[PR #34](https://github.com/RyoMurakami1983/happy-ai-work/pull/34) は相談と変更依頼を区別する方針を導入済み。2026-09-26の確認では、インストール済みテンプレートに同方針がある一方、実ホームは旧版だった。指示の改善と適用状況を区別し、過去の誤着手の原因を文面だけに断定しない。PR #34の探索的試行は正式な行動評価の完了を意味しない。

## Users / Purpose

主利用者はrepo所有者、副利用者は配布skillsを使う利用者。

- P-01: 相談と要求合意を経て、利用者が意図した時点で実装を開始できる。
- P-02: 明確で小さな変更では工程を適切に省略し、不要な確認や文書を増やさない。
- P-03: 希望する利用者がYohakuを会話開始時から継続適用でき、その選択を更新後も保てる。

## In Scope / Out of Scope

対象は、共通着手判断、PRD短縮経路と着手許可の引き継ぎ、垂直スライスの共通理解、Yohakuの任意設定と安全な設定保持、それらの説明・評価。

今回は必要な文書を作成・レビューする。配布skill・テンプレート・スクリプトの変更と行動評価の実行は後続の実装承認後に行う。実ホームへの適用、pluginの導入・有効化、Issue #35・#29の実装、PR公開・merge、Constitution変更は今回の文書作成に含めない。

## Fixed Constraints / Dependencies

- 単一の明確な変更ならPRDからimplementへ直接渡せる経路を維持する。短縮の説明と許可確認を必須にし、取得済みの同じ許可を聞き直さない。
- 垂直スライスの定義と短縮条件は分ける。新しい構造判断をPRDで作らない。
- home-bootstrapのdry-run、差分提示、backup、明示承認、管理外の保持を維持する。
- Yohakuは任意配布のpreview skillのまま。未導入環境にも共通方針を提供する。
- 全作業への固定的な工程数・文書数や、同じ規則の全repo複製を要求しない。
- 今回の方針は共通方針の項目数そのものを目的にしない。PRD 008の「6項目固定」は、本案件の任意設定を含む構成説明へ更新する対象とする。

## Unknowns / 合意状態

要求を止める未確定事項はない。選択の保存形式・CLI・配布内参照先は設計案として具体化し、独立レビューへ渡す。モデルの行動効果、plugin更新後の実読み込み、個人設定への適用結果は未検証。実装開始の許可は、この文書作成承認とは別に必要。
