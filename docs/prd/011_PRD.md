# PRD 011：技術の実現性から推奨へつなぐ調査

2026-09-30 / Issue #40 / 初版実装範囲

## 目的と根拠

未知の外部技術について、利用者が根拠・不確かさ・関係者の利益と負担を理解し、採用や追加検証を判断できることを目的とする。

根拠は[Issue #40](https://github.com/RyoMurakami1983/happy-ai-work/issues/40)、[提案書](../../incubator/technical-feasibility-research/PROPOSAL.md)、2026-09-29の中立性・合理性・Win-Winの方針への賛意と、2026-09-30の「OKです。作成進めてください。GPT6用として」。後者を、提案した初版の作成とローカル検証の承認として扱う。

## 要件と受入条件

| ID | 成立すべき条件 | 観測可能な受入条件 |
| --- | --- | --- |
| R1 | 設計を左右する未知に調査を絞る | 未知の成立条件を扱い、単純なAPI確認や既存技術で足りる変更には広い比較を追加しない |
| R2 | 資料・静的確認・実測を分ける | 出典・版・環境・確認範囲を追え、未確認と非対応を区別する。資料と実測が食い違えば実測の条件を残す |
| R3 | 中立的に推奨する | 好む候補が必須条件を満たさなければ推奨を変える。重みや未知で順位が変わるときは条件を示す |
| R4 | Win-Winを負担も含めて検討する | 組み合わせの利益と接続・配布・保守負担を比較し、成立時だけ相乗効果を推奨理由に使う |
| R5 | 調査を判断と次の行動へつなぐ | 採用・条件付き・見送り・保留の推奨、理由、見直し条件、次の作業を示す。採用決定・実装許可と混同しない |
| R6 | 調査票を再利用し既存成果物を守る | 日本語の題名で新規調査票を作成でき、既存ファイルへの再実行は失敗して内容を保持する |
| R7 | 既存の設計スキルと併用・単独利用できる | technical-designに呼出し条件と取込み方を追加し、未導入でも設計作業を続けられる。委譲は必要時・許可範囲内で行える |
| R8 | GPT-6向けに範囲と完了条件を明確にする | 短い起動説明と判断上必要な境界を持ち、固定された詳細手順・全候補探索を強制しない。実際に確認したモデルと検証限界を記録する |

対象はスキル本文、雛形、初期化補助、判断例、設計スキルとの連携、公開可能な架空ケースでの検証。特定GUIの採否、既存アプリの移行、万能情報収集器、homeや導入済みcacheの変更、外部公開・PR・mergeは含めない。

## 完了条件と限界

補助スクリプトの公開CLI検証、スキル形式と参照検証、repo品質チェック、固定した架空ケースの独立した生成・採点を完了する。基本検証後はhappy-previewで試用する。実利用の効果、全GPT-6モデルでの再現性、実際の自動起動は今回の模擬確認だけでは証明しない。

観測条件の詳細は実行前に固定する評価caseを正本とする。利用者の優先事項をモデルが勝手に決めず、判断に影響する不足のみを確認する方針であり、全案件に正式なPRDや数値目標を要求しない。
