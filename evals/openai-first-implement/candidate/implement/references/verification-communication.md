# 検証の開始前通知と終了報告

Refs #44 / #45。検証commandを実行する前に、repoのtest分類・script・計画から、全件suiteに長い試験が含まれるか確認する。計画なしのバグ修正でも同じ扱いにする。

長い検証、負荷・耐久試験、実環境や外部資源を使う検証は、実行ツールを呼ぶ前に目的、規模・区分（合成入力／一時fixture／実環境）、所要時間の見込みを短く伝える。計測値がないなら見込みまたは不明と明記し、timeout・試行budgetや過去記録から根拠を示す。全件suiteへ含まれる長時間部分も省かない。

通知は承認要求ではない。同じ範囲で承認済みなら返信を待たず進める。短い通常testに通知や確認待ちを増やさない。新しい課金、認証変更、許可を超える負荷・本番操作などが必要なときだけ、その影響と必要な判断を示して該当操作を保留する。

終了時は結果とその意味、未確認の範囲、次の判断・行動があればそれを伝える。合成testの成功を実環境の成功へ広げず、未実行・失敗・timeoutを区別する。証拠の詳細はhandoffへ残し、ユーザーへ全logや内部手順を再読させない。完了済みで判断事項がなければ追加質問をしない。
