# 適用例と観察条件

以下は共通の観点を具体化する例であり、実装方式や全案件共通の数値基準ではない。既存の要件・対象環境に合わせ、必要な場面だけを使う。

## UIの応答性

長い処理を始める場面では、利用者が「押せたか」「待つ必要があるか」「次に何ができるか」を分かるようにする。

- 極め：入力を受け付けた応答と処理結果の確定を分け、必要な時点でそれぞれを返す。
- 残心：待機中の操作、中断・再操作、遅れて返る結果が、利用者の現在の意図と食い違わないか確かめる。失敗時も状態と次の操作が分かるようにする。
- 観察：代表操作の入力から受理表示まで、結果確定までの時間を別々に測る。合意した操作が待機中も可能か、中断後に不要な結果が現れないかを確認する。測定条件と件数を残し、平均だけで遅い例を隠さない。

「すぐ表示できた」だけでは、正しい結果が届いた証拠にならない。逆に、結果を確定するまで無反応である必要もない。

## 保存の確実さ

利用者が作業を離れ、あとで再開する場面では、「保存済み」が何を保証するかを先にそろえる。

- 極め：合意した保存の保証を満たした時点で、保存済みと伝える。受付や送信の終了を、そのまま保存完了と扱わない。
- 残心：あとで開き直して必要な内容を使えるか、中断・失敗時に何が残るか、重複や上書きを避けて再開できるかを確認する。
- 観察：対象の保存先から再読込した内容と期待値を照合する。合意した故障条件で、失われた変更、重複、回復までの手順・時間を記録する。再読込の成功だけで、未確認の障害への耐久性まで保証しない。

具体的な保存方式や復旧手段は、必要な保証と影響範囲から設計する。

## 引き継ぎの完了

成果物を渡す場面では、送った事実に加えて、受け取る人が次の作業を始められる状態を見る。

- 極め：判断・実行に必要な内容を、必要な相手へ必要な時点で渡す。
- 残心：アクセス可否、成果物の版、未完了事項と再開点を確認できる範囲で確かめる。相手の確認が必要な契約なら待ち、そうでなければ不要な返答待ちを完了条件に加えない。
- 観察：合意した受け渡し条件の充足、開始を妨げた不足、確認し直した回数を記録する。未確認の受領や理解を確認済みと書かない。

## 試用で確かめること

試用前に、対象場面、期待する行動、守る条件、観測方法を固定する。上の例に加え、単なる用語説明や文章推敲では不要な工程を増やさないかを見る。

- 応答と確定を適切に分けられたか。
- 完了の主張と、実際の確認範囲が一致したか。
- 重要な中断・失敗から、許可範囲で再開できたか。
- 相手や周囲への負担を減らし、別の遅延・損失・重複へ付け替えていないか。
- 確認や説明の追加負担が、得られた効果に見合ったか。

これは観察計画であり、検証結果ではない。効果を比較する場合は同じ課題と基準で実行し、事例数・確認済み範囲・限界を残す。未測定の改善率や一般的な優位を述べない。
