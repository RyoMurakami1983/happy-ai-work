# Home Bootstrap

`scripts/home_bootstrap.py` は、`CODEX_HOME` があればその配下、なければ `~/.codex/AGENTS.md` を対象にする。管理対象マーカー内だけを追加・更新し、既存の他セクションは変更しない。

skillやテンプレートの改善依頼ではrepo内の成果物を更新する。実homeへの適用も依頼されている場合は、対象と差分を示してその承認範囲で進める。既に得た適用承認を聞き直さない。

実homeへ導入・更新する場合は次の手順を使う。テンプレートの動作確認は、一時ファイルを`--target`に指定して行える。

1. 対象の管理領域・周辺の個人設定と、下記のYohaku選択状態を確認する。未設定かつ利用可能なら常時適用の希望を先に尋ねる。
2. 選択を反映した `python scripts/home_bootstrap.py --dry-run` を実行して対象pathとdiffを示す。通常更新は`--yohaku preserve`（既定）、承認された選択変更は`--yohaku enable`または`--yohaku disable`を付ける。
3. ユーザーが適用を明示した場合だけ、確認した差分と同じ引数で `--apply` を実行する。
4. 既存ファイルを変更するときは、同じディレクトリへtimestamp付きbackupを作る。
5. 適用後に管理対象セクション、選択状態と管理外の内容が保持されていることを確認する。

home指示には普遍的な作業方針だけを置く。言語・framework・test commandなどrepo固有の規則は各repoの `AGENTS.md` に置く。

## 共通方針への融合

基本方針の正本は [assets/AGENTS.md](assets/AGENTS.md)。Yohakuを常時適用すると選択した場合だけ、[開始時の指示](assets/yohaku-startup.md)を既存の一つの管理領域へ合成する。読者別の説明、比較の型、コード簡素化などの詳細は`yohaku`が担当する。Yohakuが未導入でも基本方針だけで使える。

「目的を把握する」は会話やrepoから判断する段階、「必要な情報から報告する」は伝える段階として扱う。指定された詳しさや書式、判断に必要な条件を短さのために削らない。

実homeへの適用時は対象ファイルの管理領域と周辺の利用者設定を読み、意味の重複や競合を確認する。配布テンプレートだけの改善ではrepo内の管理領域を対象にする。管理外の個人設定は自動削除しない。競合があれば該当箇所と影響を示し、融合案を提示してから適用する。

## 任意のYohaku開始時設定

現在の選択可能なskill一覧にYohakuがあり、その本文を読める場合を「利用可能」とする。キャッシュファイルの存在だけでは判定しない。自動導入・有効化は行わない。

管理領域内の`<!-- happy-ai-work:yohaku=enabled -->`は常時適用、`disabled`は常時適用しない選択を表す。コメントがなければ未設定。未設定で利用可能な場合は「新しい会話の開始時にYohakuを読み、会話中の説明・成果物へ適用する設定を追加しますか」と尋ね、選択を差分へ反映する。無回答を無効化の選択とみなさない。

設定済みなら通常更新で選択を保持し、毎回聞き直さない。利用不可の場合も保存済みの選択は削除せず、共通方針で作業を続ける。会話内の解除はその会話の適用を終了し、永続設定を変更しない。今後も無効にする依頼は`disable`の差分を提示する。

状態コメントは更新用metadataであり、新しい管理領域のマーカーではない。不正・重複・未知値や管理領域の破損でscriptが拒否した場合は、差分と修復案を示してから対応する。`--template`は状態コメントを含まない基本テンプレートを指定する。旧版のscriptへのdowngradeでは選択保持を保証できないため、適用前の差分とbackupを確認する。

配布物の更新、pluginの更新、実homeへの適用、新しい会話での読込確認を別の到達状態として報告する。

## Git設定

AGENTS.mdへGit固有の指示を追加しない。homeの初回導入、またはユーザーがGit設定を求めたときは、[Git設定ガイド](references/git-settings.md)を読み、3つの入力欄へ貼り付ける文面と「準備完了時に自動マージ」をONにする手順を表示する。既存の共通方針だけを更新する依頼では、その変更結果に絞る。

Codexアプリ自身の設定画面を確実に自動操作できない場合、設定済みと推測せず手動入力が必要だと明記する。

## Hooks

Hooksの確認または設定を求められたときは、[Hooks初期設定ガイド](references/codex-hooks.md)を読む。未設定は異常ではない。既定ではhookを書き込まず、既存設定のinventoryと候補の説明まで行う。設定変更は候補ごとに影響を示し、dry-run、差分確認、ユーザーの明示承認、backup付き適用、Trust確認の順に進める。
