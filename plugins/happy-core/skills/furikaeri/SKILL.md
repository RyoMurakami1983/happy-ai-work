# ふりかえり

進捗報告だけで終わらせず、次回の行動が変わる学びを一つ以上残す。会話を正本とし、ユーザーが依頼しない限りfile、Issue、外部serviceへ保存しない。

## モード

- **Quick YWT**: 短く素直な作業。やったこと、分かったこと、次にやることを整理する。
- **KPT**: 複数工程、詰まり、出戻り、再発、日次横断がある作業。Keep、Problem、Tryを整理する。

## ワークフロー

1. 対象期間と当初の目的を確認する。
2. 実際に起きたこと、完了したこと、未完了、重要な判断を時系列で短く並べる。
3. 摩擦が軽ければYWT、再発や構造問題があればKPTを選ぶ。
4. Problemは人ではなくprocess、道具、前提、情報、環境へ向け、観測事実と解釈を分ける。
5. Tryは一度に試せる小さい行動にし、owner、次の機会、確認方法を置く。
6. 複数回再発し、対象と受け入れ条件が明確なものだけ追跡候補にする。すべてをIssue化しない。
7. 保存やIssue作成は候補を示した後、ユーザーの明示依頼を得て別工程で行う。

## 出力

- 対象と達成事項
- YWTまたはKPT
- 次回試す行動（最大3件）
- 追跡候補と、今すぐ起票しない項目
- 必要なら残存risk／未完了

秘密情報、個人data、社外公開できない案件情報は、保存・共有候補から除外または匿名化する。
