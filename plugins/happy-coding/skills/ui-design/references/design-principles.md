# UI Design Principles

## 人間中心の判断

主要タスクを最短操作数だけで測らない。利用者が今の状態、次にできる操作、操作後の結果、失敗からの復帰を理解できるかを確認する。頻度の低い操作でも、影響が大きければ意図確認と復帰方法を優先する。

## 情報構造

- **近接**: 関連する情報と操作を近づけ、無関係なものを混ぜない。
- **整列**: 読順、関連、入力と結果の対応を揃える。
- **反復**: 同種の情報、状態、操作に同じ表現を使い、例外には理由を持たせる。
- **対比**: 主目的、現在状態、破壊的操作を区別できるようにする。

これらを装飾規則として数値化しない。利用者が誤った関連や優先度を推測しないかで判断する。

## 操作とfeedback

affordanceはcontrolが実際に持つ操作可能性、signifierはlabel、形、配置、icon、cursor、説明など利用者へ伝える手掛かりである。signifierだけを追加しても機能しない操作を作らず、操作可能でも手掛かりがなければ発見・理解できない問題として扱う。

操作後は進行中、成功、失敗、取り消し可能性を適切な場所と時間で示す。表示する値、enabled状態、結果表示は同じsource of truthを表す。

## Command hierarchy

primary commandは主タスクを進める一つの明確な操作、secondary commandは補助操作、destructive commandは削除・破棄・不可逆変更である。destructive commandをprimaryと視覚的に競合させず、頻度と回復可能性に応じて確認、undo、隔離を選ぶ。

## アクセシビリティ

意味のあるcontrolに名称を与え、論理的なfocus順と見えるfocus indicatorを保つ。色以外にも文言、icon、形、位置などで状態を伝える。対象の最小viewportで主タスクが隠れず、拡大時にも読順と操作が維持されることを確認する。
