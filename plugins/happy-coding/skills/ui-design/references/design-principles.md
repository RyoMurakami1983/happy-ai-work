# UI Design Principles

## 人間中心の判断

主要タスクを最短操作数だけで測らない。利用者が今の状態、次にできる操作、操作後の結果、失敗からの復帰を理解できるかを確認する。頻度の低い操作でも、影響が大きければ意図確認と復帰方法を優先する。

## メンタルモデルと一貫性

配置・装飾の前に、対象利用者が慣れたOS・アプリ・業務用語と、主要操作から予測する結果を確かめる。既知の会話・資料・画面を再利用し、不足する判断材料だけを確認する。安全性・アクセシビリティ・業務要件と両立する範囲で、そのメンタルモデルに合う操作を第一候補とする。

外的一貫性（対象プラットフォームや分野の慣習）とアプリ内の一貫性を照合する。「選択」と「開く」、「戻る」、拡大・移動などは対象環境の標準操作を起点にするが、利用者の期待、観測した慣習、設計者の仮説を区別する。OS・入力機器・アプリで異なる操作を「誰もがそう考える」と一般化しない。

主要操作は「予測する操作・結果 → 採用する動き → 確認方法」を既存設計へ短く結び付ける。例えば写真ビューアでは次の観点を対象環境に合わせて具体化する。特定のgestureやキー割当を全アプリへ強制する例ではない。

| 予測する操作・結果 | 採用する動きの例 | 確認方法 |
| --- | --- | --- |
| 月カレンダーで写真のある日を見分け、選ぶとその日の写真が出る | 写真の有無を件数・印など色以外でも伝える | 写真あり・なしの日を表示し、日を選んだ結果を確認する |
| 対象環境で慣れた方法で複数選択し、別の操作で開く | 単一・追加解除・範囲選択と開く操作を区別し、選択状態・件数を伝える | 対象のキー・ポインター操作で選択集合、focus、開く対象を確認する |
| 見ている位置を保って拡大し、拡大後に上下左右へ移動する | 対象機器でのピンチの基準位置と2本指パン、移動端、復帰操作を定める | 拡大前後の注目位置と両軸の移動・復帰を連続操作で観測する |

慣習と安全・アクセシビリティ・業務要件が衝突する場合は単純に模倣しない。例えば即時削除に慣れていても、対象確認が必要な業務では対象と影響を表示して確認し、可能ならundoなどの復帰経路を設ける。例外理由、理解できるlabelやfeedback、keyboard等の代替操作を示す。

## 情報構造

- **近接**: 関連する情報と操作を近づけ、無関係なものを混ぜない。
- **整列**: 読順、関連、入力と結果の対応を揃える。
- **反復**: 同種の情報、状態、操作に同じ表現を使い、例外には理由を持たせる。
- **対比**: 主目的、現在状態、破壊的操作を区別できるようにする。

これらを装飾規則として数値化しない。利用者が誤った関連や優先度を推測しないかで判断する。

## 操作とfeedback

affordanceはcontrolが実際に持つ操作可能性、signifierはlabel、形、配置、icon、cursor、説明など利用者へ伝える手掛かりである。signifierだけを追加しても機能しない操作を作らず、操作可能でも手掛かりがなければ発見・理解できない問題として扱う。

操作後は進行中、成功、失敗、取り消し可能性を適切な場所と時間で示す。表示する値、enabled状態、結果表示は同じsource of truthを表す。

## Command hierarchy

primary commandは主タスクを進める一つの明確な操作、secondary commandは補助操作、destructive commandは削除・破棄・不可逆変更である。destructive commandをprimaryと視覚的に競合させず、頻度と回復可能性に応じて確認、undo、隔離を選ぶ。

## アクセシビリティ

意味のあるcontrolに名称を与え、論理的なfocus順と見えるfocus indicatorを保つ。色以外にも文言、icon、形、位置などで状態を伝える。対象の最小viewportで主タスクが隠れず、拡大時にも読順と操作が維持されることを確認する。
