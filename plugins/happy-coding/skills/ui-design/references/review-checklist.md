# UI Review Checklist

## 設計の起点

- 配置や装飾より先に、対象利用者、慣れたOS・アプリ・業務用語、主要操作から予測する結果を確認したか。既知の内容を再質問していないか。
- 安全性・アクセシビリティ・業務要件と両立する範囲で、メンタルモデルに合う操作を第一候補にし、外的一貫性とアプリ内の一貫性を照合したか。
- 利用者が述べた期待、観測した慣習、設計者の仮説を分けたか。
- 慣習を外れる場合、理由、理解・発見の手掛かりと復帰方法があるか。
- 主要操作の「予測する操作・結果 → 採用する動き → 確認方法」を短く追えるか。十分な合意済み設計を再利用し、変更に無関係な設計・文書・一律確認を増やしていないか。

## フローと状態

- 誰が何を完了したいか、最初の一手は明確か。
- empty、loading、active、success、errorと必要な例外状態に、理解可能な次の行動があるか。
- disabled、処理中、完了の表示が実際の状態と一致するか。
- errorから再試行、修正、取消、支援へ戻れるか。

## 構造と操作

- 関連情報と操作が近接・整列し、主目的が対比で分かるか。
- primary、secondary、destructive commandが競合していないか。
- controlは操作可能であることを示し、labelと結果が予測可能か。
- 自動選択やfallbackが利用者の選択を黙って置き換えていないか。

## アクセシビリティと検証

- キーボードだけで主要controlに到達・操作でき、focusが見えるか。
- label、error、statusは色だけに依存しないか。
- 最小viewportと拡大時に主タスクを完了できるか。
- build、内部値、screenshotだけで結論にせず、変更した期待に関わる代表操作・状態変化・feedbackをruntimeで確認するか。
- 自動runtime確認、実機の物理gesture、利用者本人の受け入れについて、確認済みと未確認の範囲を分けたか。
