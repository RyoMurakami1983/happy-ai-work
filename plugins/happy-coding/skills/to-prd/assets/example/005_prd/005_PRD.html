PRD: CSV取込前の確認 — 架空例

Context

取込担当者は、CSVの行を確認する前に反映されると、形式不備や対象の選び間違いに気付けない。この例は資料表示を確認するための合成ケースであり、実利用者の調査結果ではない。

Problem

確認前の更新を防ぎ、有効・無効の理由と確認対象を区別してから取込を判断したい。

Users

CSVから取込対象を確認する担当者。新しいroleや権限policyは、この例では定義しない。

Agreement Status

架空の入力資料では、P-01 / P-02とR-01 / R-02を合意済みとしている。R-03とAC-03 / AC-04は未合意の候補で、U-01の確認後に要求へ反映する。実装許可は未取得。これはスキルの表示例であり、実案件への承認ではない。

Purpose

目的実現したい状態根拠
P-01確認前の誤取込を避ける合成入力S-01
P-02対象と除外理由を理解して判断できる合成入力S-01

In Scope

  • 必須列不足の拒否と、更新しないことの確認。
  • 有効・無効行と理由のプレビュー。
  • 確認対象の選択・取消と、確認後の取込はR-03の候補範囲。確定にはU-01の回答が必要。

Out of Scope

  • CSVを自動補正して取込むこと。
  • 定期実行、無人での反映。
  • role・権限policyの変更、architecture、実装順の選定。

Requirements

要件成立すべき条件対応する目的根拠・合意状態
R-01必須列が足りない入力を拒否し、取込先を更新しないP-01S-01・架空の合意済み条件
R-02有効・無効行と無効の理由を更新前に確認できるP-02S-01・架空の合意済み条件
R-03選択・取消と確認対象が一致し、確認した対象だけを反映するP-01S-02・未合意の候補、U-01待ち

Acceptance Criteria

AC対象要件前提・操作観測できる期待結果
AC-01R-01必須列が足りないCSVを入力する不足項目が表示され、取込先に更新がない
AC-02R-02有効・無効の両方を含むCSVをプレビューする有効・無効の行と無効理由を区別でき、取込先に更新がない
AC-03（候補）R-03対象を選択・解除し、確認を取消す確認対象が選択と一致し、取消後に更新がない
AC-04（候補）R-03確認対象を反映し、反映失敗も試す対象外は反映されず、失敗を完了と表示しない。部分反映の扱いはU-01で確定する

Fixed Constraints

合成入力はCSVを使用する。DB方式、UI framework、API方式は未選定で、PRDで決めない。

Dependencies

R-03の反映を受け入れるには、確認済みの取込先と実行権限が必要。取込先・権限の実確認は未実施。

Unknowns

ID未確定事項影響する目的・要件次工程を止めるか確認先
U-01部分反映が起きた場合の要求と、取込先・権限P-01、R-03、AC-03 / AC-04R-03の要求確定と反映の受入を止める。R-01 / R-02の整理は可能利用者・取込先管理者
U-02許容する文字コード、必須列の具体名R-01 / R-02入力contractの確定を止める利用者の代表CSV
U-03「判断しやすい」を測る条件P-02表示ACだけで価値達成とは判定しない利用者

Source Notes

  • S-01：この表示例のための合成入力。更新前の入力拒否・有効無効の確認を架空の合意済み条件として与えた。
  • S-02：この表示例のための合成候補。選択・取消・確認対象の取込を提案し、部分反映の要求は未合意とした。
  • アプリ、取込先、権限、読解効果は未検証。草案の保存とHTML生成は、要求成立や実装開始の許可を意味しない。
