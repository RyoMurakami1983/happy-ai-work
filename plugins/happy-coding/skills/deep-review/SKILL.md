# Deep Review

固定agentファイルに依存しない。subagentが利用可能なら、差分と最小要件だけを渡して独立レビューを依頼する。複数モジュールにまたがる移行の互換性や、データ損失につながる失敗経路を追う場合は、利用可能な `gpt-6.2-astra` をレビュアーの候補にする。subagentが利用できなければ新しい観点でローカル差分を読み直す。Copilot CLIはユーザー明示時だけ実験的に追加し、結果をコード・testで再検証する。

変更前の準備・正本・非破壊性・配布経路の確認、および複数案／決定変更後にAGENTS.md・SKILL.md・reference・README・実装・test等の恒久成果物を変更した場合は[preflight.md](references/preflight.md)を読み、instruction finalizationを独立確認する。module境界・結合構造自体が主題なら[modularity.md](references/modularity.md)を読む。

外部ツールのテストでは、[実行ファイルの代役に関する基準](../implement/references/verification-communication.md)に照らして別製品名での配置を指摘する。

## レビュー手順

1. diff、合意した目的・AC、test結果、repo instructionsを照合する。局所修正やtest成功だけで目的へ届くとみなさず、未合意の要件を追加しない。
2. 変更に応じ、正しさ・回帰・data損失・権限／機密・並行性・エラー処理・test妥当性・責務境界を調べる。構造の過不足は理解・変更・検証への具体的影響で判断し、応答・保存・中断・再試行が関わるなら結果と失敗後の状態を確かめる。日常の現場利用に渡せるか。
3. 各候補の行・発生条件・影響・反例を確認し、再現／論証が弱い指摘を除く。違和感を証拠にせず、重要でも根拠不足なら未確認事項へ分ける。
4. 重要度順に、場所・問題・発生条件・影響・根拠・最小修正方針を、重要な指摘が埋もれない形で返す。
5. なければ「重大な指摘なし」とする。

指摘の有無にかかわらず、確認範囲・未確認事項・残存riskを短く示す。調べた根拠・保留理由と確認できた影響を対応させ、静的な論証と実動作確認を区別する。確認待ちでは独立した調査と再開条件を分け、許可のない外部連絡はしない。「重大な指摘なし」は未検証の動作保証やマージ承認ではない。

レビュー中は変更しない。修正まで依頼された場合だけ指摘確定後の別工程で実装する。スタイルの好みを不具合にしない。
