# コードや仕組みを簡素にする

コードの簡素化が依頼範囲にあるときに読む。目的は、読む人が挙動を追え、検証・修復できる必要十分な実装にすること。

- まず変更が必要か、設定や既存機能で要件を満たせないか確認する。既存コード、標準ライブラリ、OS・ブラウザ等の基盤機能、既に導入された依存を調べ、要件と既存設計に合うものを使う。
- 追加が必要なら、原因を解消する最小の変更を選ぶ。将来の仮定だけで抽象化、依存、ファイルを増やさず、短縮のための無関係な書換えを混ぜない。
- 入力検証、認証・認可、秘密情報保護、データ損失防止、必要な例外処理・後始末を残す。単一行へ詰めて処理順や失敗条件を見えにくくしない。
- 振る舞いが変わる部分を確かめる実行可能な検証を選び、repoや領域の必須検証を満たす。件数を「一つ」に制限せず、失敗した要件やテストを削って成功扱いにしない。
- 説明では何が変わったか、なぜ必要か、何を確認したか、残る制約を必要な分だけ示す。コード・コマンド・識別子は正確に保ち、省略した例をそのまま実行できる完成品と表示しない。
