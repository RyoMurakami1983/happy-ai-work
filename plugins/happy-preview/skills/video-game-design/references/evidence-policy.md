# 根拠と暗黙知

人物の考えを追加・更新するときに使う。共有会話や検索結果の要約は資料を探す入口であり、発言の確認済み根拠にはしない。

| 種別 | 記録する内容 | 帰属の注意 |
| --- | --- | --- |
| A 本人発言 | 本人の講演、著書、インタビュー、公式動画 | 誰の発言か、対象作品と文脈を確認 |
| B 共同開発者の証言 | 当事者が見た行動・判断 | 証言者と対象人物を分ける |
| C 制作記録 | 試作、制作後の振り返り、変更履歴 | 記録から分かる変化と理由の推定を分ける |
| D 第三者分析 | 研究者・批評家・他の開発者による作品分析 | 分析者の原典を読み、本人の意図と呼ばない |
| E スキル側の推定 | 複数資料や作品から導いた仮説 | 推定と明記し、確認済み発言に昇格しない |

同じ資料に複数種別がある場合は主張ごとに分類する。分類は信頼度の点数ではない。本人の一般論にも文脈上の限界があり、第三者の具体的分析が試作に役立つこともある。

カードには、人物／分析者、資料タイトルとURL、確認箇所、種別、確認できた事実、実務への翻訳、適用限界を持たせる。短い要約を優先する。動画の概要だけ読めた場合、動画全編を確認したと扱わない。閲覧不能なら未確認と残し、名前の数合わせに使わない。

暗黙知は「観測された行動→考えられる判断→今回試す操作」の順で翻訳する。例えば身体を使って動きを伝えたという証言から、操作の感触を短い動作デモで比較する案は作れるが、その人の普遍的な設計法とは断定できない。

作品横断の推定には独立資料・別作品・反例を探す。同一記事の転載やその記事だけを引用する解説を独立証拠として数えない。反例が見つからないことも証明にはしない。根拠不足でも試す価値がある案はEの仮説として小さく検証できる。

人物への帰属とスキルの提案は分離する。「宮本ならこう言う」などの架空発言を使わず、「この記録から本スキルでは○○を試す」と書く。原則が衝突したら、今回届けたい体験に対する効果とコストを比較し、必要なら試作を分ける。
