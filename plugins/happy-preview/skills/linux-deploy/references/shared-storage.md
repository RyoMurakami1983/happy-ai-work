# 共有参照元と専用保存先

## パスを決める証拠

共有名、共有内の相対パス、ホストのmount先、アプリから見えるパスを別項目として対応づける。利用者の表示名に区切りらしい文字があっても、確認せず階層と解釈しない。

対象ホストで、引用した実パスに対して`realpath --`、`stat --`、`namei -l --`等の利用可能な道具を使い、解決先・所有者・通過権限を確認する。秘密を含むmount optionや共有内のファイル一覧を無制限に出力しない。

`findmnt --target`は祖先のファイルシステムも返す。終了値0やディレクトリの存在だけで共有接続済みと判断しない。期待する共有の種類・接続元・mount先と照合する。FSROOTの表示はFSや方式で異なるため、`/`か特定文字列かを普遍的な成否条件にしない。

自動マウントでは同じmount先に`autofs`と実際の共有が重なる場合がある。`autofs`だけで接続成功・失敗を決めず、対象パスへの必要な読取アクセスで接続を起動してから実際の共有を照合する。例えばCIFSでは、対象ディレクトリ内の`.`を`stat`した後、`findmnt --mountpoint "$mount_path" --types cifs --output TARGET,SOURCE,FSTYPE`で共有の層を選べる。種類で絞るだけでは十分ではなく、接続元とmount先も期待値に一致することを確認する。共有が確認できない間は、残ったローカルディレクトリへ書き込まない。

## データ契約の確認

許可されたテスト共有に、期待するサブフォルダ、範囲外の兄弟フォルダ、専用保存先を用意する。実サービス権限で次を確かめる。

- 期待する既知のテストデータを読める。空一覧やhealth成功で代用しない。
- 契約上の範囲外を参照できない。アプリ内のパス指定だけでなく、渡しているmount範囲も確認する。
- 原本相当のテスト領域への書込みが拒否される。実際の原本へ書いて試さない。
- 保存先に一意なテストファイルを作成・再読でき、意図した保存先に存在する。削除する場合はその試験が作ったファイルだけを対象にする。

共有未接続の試験では、本番共有を外さず、専用テストmount／環境を使う。mount先だけが残っている状態で適用が止まり、ローカルへ誤保存しないことを確認する。接続先や認証が未提供なら共有検証は未実施と記録し、ローカルディレクトリの試験をSMB／NFSの検証へ読み替えない。

制御したアンマウント後の再接続、ホスト再起動後の共有復帰、処理中のネットワーク断からの復旧は別の試験として記録する。ホスト再起動は再接続後にboot IDの変化などで完了を確認し、実行権限でのデータアクセスも再確認する。共有の復帰だけではアプリの自動起動・起動順序・処理再開を証明しない。依頼に関係する範囲を試験し、未実施の障害への耐性へ読み替えない。
