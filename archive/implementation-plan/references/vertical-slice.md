# 垂直スライスと工程の短縮

sliceの境界を決めるとき、または設計・計画を省略して実装へ渡すときに読む。

## 垂直スライス

利用者または外部の呼び出し元から観測できる、一つのまとまった振る舞いを、必要な層にまたがって実現・検証する変更単位。一つのsliceに正常系・境界条件・失敗時など複数の受け入れ条件を含めてよい。

- ファイル数・層数・受け入れ条件の数で単一かを決めない。
- 例えば設定の保存と不正値の拒否は、同じ振る舞いとして検証できる。
- 一つの決済操作でも、新たな認可・外部連携の判断が必要なら設計を行う。単一であることは小規模・低risk・設計不要を意味しない。
- 文言・文書・設定の局所修正を説明するために、不要な層の変更やslice分割を加えない。特定のvertical slice architectureの採用も要求しない。

## 単一の明確な変更として直接実装へ渡す条件

一つのまとまった振る舞い、または明確な局所修正について、次をすべて確認する。

1. 目的・対象範囲・受け入れ条件が明確。
2. 既存の構造・規約に沿う方法が明確で、新しい構造判断が残っていない。
3. 複数作業の依存・順序の調整が残っていない。
4. 変更範囲に合う検証方法が明確。
5. [成果物の保存・省略条件](WORK_ARTIFACTS.md)と整合する。複数repo、公開契約、長期的な構造、互換性、移行・運用への影響を、単一sliceという理由で省略しない。

不足する要求は要求整理へ、構造判断はtechnical-designへ、順序・分割はimplementation-planへ戻す。PRDで新たな技術設計を行って短縮条件を満たしたことにしない。

## 短縮の説明と実装許可

PRDから直接implementへ渡す場合は、対象範囲、省略する設計書・計画書、設計レビューの要否と具体的な理由を示し、その内容での実装可否を必ず確認する。例:

> 今回はボタンの文言だけを変更し、処理や権限は変えません。単一の明確な変更のため、PRDのみで設計書と計画書は不要です。既存の表示文言だけなので設計レビューも省略できます。このPRDの内容で、そのまま実装してよいですか？

PRDへの賛意は実装許可ではない。同じ対象・範囲・省略内容について利用者が既に許可した場合は、該当発言を根拠として引き継ぎ、再質問しない。範囲や省略内容が変わった場合は、その変更部分を確認する。

handoffには、対象・範囲、省略工程と理由、実装許可の状態と根拠となる利用者発言、未確定事項と戻り先を残す。明確に任された局所修正を形式のためだけにPRDへ戻さない。
